# ADR 0011 — 以真实连接区间验收并发

2026-11-06。

旧压测在阶梯启动客户端、每条连接完成三轮后关闭，再等待进程满 120 秒。旧本机报告中每客户端仅约 25–33 秒，不能证明 T16 要求的十条连接共同连续运行两分钟。保留旧报告历史，撤回 T16 勾选，使用新测量补证。

新 runner 同时启动独立客户端，以单调时钟记录每次 `session.ready` 到断开/主动结束的区间。完成三轮后仍按 100ms 上传静音，定期应用 ping/pong 检查；收到有效转写和其后响应音频才计成功。退出和异常路径关闭 WS，重试不拼接断开的时间。验收函数计算每个独立客户端各一条完整区间的共同交集；十客户端、30 次尝试至少 29 成功、共同区间 ≥120 秒才通过。短时或单客户端 smoke 明确不达 T16。

首音频延迟从输入文件上传完成计时，不把后加的 1.5 秒 VAD 静音当作用户仍在说话；不测浏览器实际播放延迟或人的听感。上游在输入结束前输出时不填该轮回答延迟。输入为仓库 macOS TTS，缺失、空文件、非 PCM16 字节长度直接失败，不能退回纯音并冒充语音。

报告包含运行与部署版本、UTC 时间、每客户端区间、上传/接收字节、延迟和错误。每轮保存带时间戳的私有 JSON，另更新最新文件；不存音频、转写或票据。显式 `--real-provider` 才调用付费中继。测试覆盖旧短连接假阳性、交集、重连间隙、无效/重复客户端以及 29/30 门槛。

T16 的样本使用许可、T06 真人中英各三轮、T08 实体手机、T15 现场音响与 T19/T20 招募传播指标仍须各自证据；本 runner 不能替代这些验收。
