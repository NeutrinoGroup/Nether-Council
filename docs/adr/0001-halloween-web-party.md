# ADR 0001 万圣节 Web 语音派对架构

日期：2026-11-01  
状态：采用；协议、账号和性能按实施闸门验证。  
关联：[产品规范](../../specs/001-halloween-party/spec.md)、[实施计划](../../specs/001-halloween-party/plan.md)、[任务清单](../../specs/001-halloween-party/tasks.md)。

## 背景

Issue 1–3 最初围绕 3D AI 狼人杀规划。产品访谈明确核心目标是中西结合的万圣节派对，首批用户来自现有 AI／开发者／创业者社群；电脑主屏使用公共麦克风，手机扫码独立体验，完成后分享身份卡。

Issue 4 提供 Qwen Realtime 接入资料；Issue 5 要求 spec、contracts、tests、evals 和 CI。当前仓库尚无业务实现。本地 AGENTS.md 要求先证明一个双工角色和一个真实 3D 模型，再扩展。

## 决策

1. 采用 TypeScript／pnpm／Next.js 的单 Web 应用，轻量 workspace 仅拆 `contracts` 和 `party-core`，支持手机与电脑主持模式。
2. 实时语音首个实现使用 Qwen Audio 3.1 Realtime Plus，经 Vercel Node.js WS 中继保护凭据；一客户端一次一个角色，换角色重建会话。
3. 用独立文字模型适配器生成句级翻译与双语身份。字幕翻译不串入语音关键路径；身份结果通过 schema 后驱动卡片和收尾口播。
4. 七个角色的 GLB 在开发阶段离线生成与检查。首版先孟婆，再复用模板扩展；运行时只加载当前选中模型。
5. 手机与主屏没有共享房间。状态留浏览器，有界文本快照支持重连；身份卡本机生成，邀请仅携带匿名归因，不共享私人故事。
6. 10／50 人活动采用有组织的匿名事件采集与报告，不引入业务数据库。持续无人值守分析、精确全局额度或共享房间出现时，须重新评估持久化需求。
7. 交付采用真实链路闸门，确定性测试与内容／语音 eval 分开。实际活动日期未给出，不把旧方案的 24 小时目标当成交付承诺。

## 影响

保留原技术栈与开源复用目标，移除狼人杀规则、投票和隐藏信息分发。7 角色通过配置与资产扩展，不同时维护 7 条上游语音连接。主屏双语字幕和卡片增加文字模型调用与延迟，需要单独测量。

无业务数据库降低首版运维范围，也意味着没有跨设备历史、全局精确限额、长期遥测或可靠的一次性票据消费。首场以有期限的签名活动邀请、连接边界、厂商额度和人工观测控制范围；扫码自动完成入场校验，不要求手填访问码，不假设函数内计数可以覆盖所有实例。

Vercel 与 Qwen 接口以当前官方文档及实际部署结果为准。最低版本、字段、关闭策略与来源链接集中在实施计划，后续发现不符时更新计划和对应证据，不把过期 issue 示例当实现事实。
