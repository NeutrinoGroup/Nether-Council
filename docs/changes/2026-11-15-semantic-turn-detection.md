# 语义轮次检测与旁人误打断

所有角色改用 `smart_turn_v2`（threshold 0.5），由供应商结合声学与上下文判断交互意图。移除仅凭连续 40ms 音量触发取消的可选本地路径，普通启动与预热激活均持续上传麦克风音频。手动打断及供应商 `speech.started` 事件后的清空、取消与过期音频隔离继续保留。

不添加统一 500ms 延迟：`silence_duration_ms` 仅适用于 `server_vad`，在语义模式下不生效。回环 benchmark 不再按旧静音值和本地触发时长推算当前延迟改善；当前语义模式的端点与打断延迟须用真实供应商测量。

对供应商判定为 `turn_invalid` 的无效轮次，不向浏览器发送等待回复信号，避免触发并不存在的回复超时。

回归覆盖全部角色及中英文会话配置、大音量音频持续上传而不清空播放、供应商确认打断与手动打断、连续插话后的过期音频/字幕/工具隔离。真实 `qwen-audio-3.1-realtime-plus` 已回显接受 `smart_turn_v2`，并用仓库合成语音完成开场与一轮接话。模拟及合成语音测试不证明真实多人房间里的说话人识别准确率；本次不采集或注册用户声纹。

另一次真实模型检查在播报期间输入 macOS 合成的“嗯”：后续仍收到 57 块音频，没有报告语音开始或取消事件。这仅是单一样本的短附和检查。
